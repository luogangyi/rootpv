RootPV has been installed into namespace {{ .Release.Namespace }}.

Next steps:
1. Label target nodes:
   kubectl label node <node-name> ecloud.com/persistent-rootfs=true --overwrite

2. The chart configures RootPV runtime handlers on labeled nodes and uses the
   native containerd overlayfs snapshotter.

3. Wait for workloads:
   kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "rootpv.controllerName" . }} --timeout=180s
   kubectl -n {{ .Release.Namespace }} rollout status ds/{{ include "rootpv.nodeAgentName" . }} --timeout=180s

4. Check RootPV-owned node capability labels:
   kubectl get nodes --show-labels | grep ecloud.com/persistent-rootfs-ready

5. Runtime adapters use the original RuntimeClass:
   - runc-v2 handlers use the OCI wrapper.
   - Kata + QEMU handlers use the bundled task shim proxy and require an
     already working Kata/QEMU installation with explicit runtime_path/ConfigPath.
   kubectl -n {{ .Release.Namespace }} get configmap rootpv-runtime-adapters -o yaml
   kubectl get runtimeclass -l ecloud.com/managed-by=rootpv

6. For a Kata workload, submit runtimeClassName: kata-qemu and RootPV annotations.
   See docs/user-guide/kata-qemu.md and tests/e2e/manifests/kata-qemu.yaml.
   The example node/image must be adapted before applying the manifest.

Uninstall the release only after RootPV workloads and leases have been cleaned.
Generated host handlers, aliases, registry and Shadow RuntimeClasses currently
require separate cleanup according to the installation backup.
