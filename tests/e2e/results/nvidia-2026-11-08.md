## 本次发现并修复

1. GPU Operator 导入的 v3 配置与遗留 v2 主配置同时存在时，RootPV 原先拒绝发现所有 handler。
   现按生效配置版本选择 v3 runtime 表，保留 NVIDIA 源 handler 和 Toolkit 配置。
2. 70 层镜像的绝对挂载参数长 5654 字节；containerd 将 lowerdir 压缩为 `<id>/fs`，
   RootPV 原先拒绝该表示，尚未进入 NVIDIA 注入就创建失败。
   现按绝对 active upper 的快照目录还原这类路径，仍逐层核对 containerd API、目录边界、符号链接与空 active upper；
   挂载使用已有 containerd 库的线程隔离路径压缩，处理 mount(2) 参数长度限制。
3. Toolkit 切换期间源 handler 暂时消失，catalog 为空。空切片经 YAML 往返后被误判为变更，
   generation 每轮递增，导致 node-agent 重复重载 containerd。现比较切片内容，保持空 catalog 的 generation 稳定。
   在已有测试中追加重复 reconcile 断言；修复前失败、修复后通过。

未新增厂商设备发现、驱动版本分支或 MIG UUID 解析器。

## 在线结果

| 用例 | 结果 |
| --- | --- |
| 原生 containerd CDI，不填 RuntimeClass | 普通 Pod 对照通过；RootPV 三代重建通过 |
| `runtimeClassName: nvidia`，NVIDIA CDI 模式 | 普通 Pod 对照通过；RootPV 三代重建通过 |
| `runtimeClassName: nvidia-cdi` | 普通 Pod 对照通过；RootPV 三代重建通过 |
| `runtimeClassName: nvidia-legacy`，显式 UUID 管理容器 | 普通 Pod 对照及三代重建通过；OCI 中确认 NVIDIA prestart hook；不作为 device plugin envvar 分配证据 |
| `runtimeClassName: nvidia`，明确 legacy 模式 + device plugin envvar | 普通 Pod 对照及三代重建通过；Pod 申请 1 GPU，不手填 UUID；OCI 分配 UUID 与实际 GPU 一致，确认 prestart hook |
| GPU 实算 | 每次 `torch.cuda.device_count() == 1`；4096 元素平方求和为 `22898104320`，与 CPU 计算一致 |
| 持久化与设备重新分配 | marker 保留、计数 1→2→3；CDI 与 legacy envvar 重建均实际分配过不同 GPU，文件与计算仍正确 |
| 普通 sidecar | 每代使用新根目录；无 app marker、无 `/dev/nvidiactl` |
| 同一写层第二个 writer | 第二个 app 创建失败；第一个 app 的 GPU 实算与文件保持正常；失败 Pod 可正常删除 |
| node-agent 重启 | 运行中 GPU Pod UID 不变，实算继续成功；之后删除重建仍保留文件 |
| 配置空窗回归 | 在线暂时移走 NVIDIA drop-in，空 catalog 连续多轮 generation 保持不变，containerd 启动时间稳定；随后恢复配置与全部 adapter readiness |
| 恢复 CDI | 同一 legacy PVC 在 CDI 模式重建后 marker 不变，计数 3→4，单 GPU 实算通过 |
| 清理检查 | 测试 Pod、RootPV runtime state、残留挂载均为 0；7 个租约全部 released；无 GPU 计算进程 |
| 环境检查 | 节点 Ready，GPU 资源恢复可分配；Toolkit/device plugin Pod 按策略切换重建，其余原有 Pod 的 UID、phase 和重启计数不变 |

三个 CDI 入口均经真实 Webhook 注入 shadow RuntimeClass、adapter 信息和 PVC anchor，再由 catalog 安装节点 handler。
legacy 显式 UUID 用例不申请 device plugin 资源，以避免 CDI 提前注入，直接验证 NVIDIA legacy hook；
随后经批准临时关闭集群 CDI 策略，device plugin 切换为 `envvar`，将 Toolkit 模式明确设为 `legacy` 后完成分配链路验证。
Toolkit 1.19 的 `auto` 在本机使用 JIT-CDI，不能把它计为 legacy hook 证据。

普通 legacy 对照发现，device plugin 额外设置的 GDS/GDRCopy/MOFED 会导致 OCI 追加 `NVIDIA_VISIBLE_DEVICES=void`，
hook 因而跳过驱动注入。对照与 RootPV Pod 均显式设置 `NVIDIA_GDS=disabled`、`NVIDIA_GDRCOPY=disabled`、
`NVIDIA_MOFED=disabled` 后通过；本次不覆盖这些额外功能。

ClusterPolicy spec 已完整恢复，device plugin 回到 `cdi-annotations,cdi-cri`，Toolkit 回到 CDI 模式。
策略切换期间 Operator 会重写 NVIDIA drop-in；测试后已恢复备份，其内容和 Toolkit 配置均与初始备份逐字节一致。
RootPV 自动重载已恢复，四个 adapter 均已就绪；Controller 保留本次修复版本。
保留隔离的 RootPV 测试部署、local PV/PVC 和测试数据供复测，GPU 测试 Pod 已删除。
测试 Webhook 仅匹配带 `openfuyao.cn/rootpv-nvidia-test=true` 标签的 namespace。
