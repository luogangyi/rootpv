## 接入发现与处理

现有 runc-v2 adapter 已能完整委托 Ascend runtime，无需增加厂商专用 Go 分支或重复单元测试。
本轮变更为接入指南、可复用 YAML、兼容性说明和实测证据。

官方 7.3.0 安装器不能修改本环境的 containerd v3 配置，cgroup v1 分支还尝试使用旧的
`io.containerd.runtime.v1.linux`。在备份后将安装器作用于未导入的临时配置，再单独注册 v3
`ascend` runc-v2 handler。原默认 `runc` 保持不变，RootPV 不承担厂商安装器迁移。

device plugin 7.3.0 会根据自身环境中的 `ASCEND_DOCKER_RUNTIME=True` 重新决定注入方式。
将 plugin 自身放到 `ascend` RuntimeClass 后，确认采用厂商 runtime/envvar 分配；业务 Pod 只申请
`huawei.com/Ascend910`，不手填 `ASCEND_VISIBLE_DEVICES`。OCI 中确认实际分配环境与 Ascend prestart hook。

## 在线结果

| 用例 | 结果 |
| --- | --- |
| 普通 NPU Pod 对照 | 分别请求 1、2 个资源；设备数量正确，每个分配芯片实际计算通过 |
| 自动发现与准入 | catalog 生成 `ascend-runc-v2`；Webhook 注入 `persistent-rootfs-ascend`、adapter 信息和 PVC anchor；节点 readiness 就绪 |
| 路由尚未就绪 | 启用 RootPV 的请求被明确拒绝，不回退到普通临时根目录 |
| 三代持久化 | 每代请求 2 个资源；marker 不变、计数 1→2→3，重新分配芯片后计算仍正确 |
| 原厂委托 | 每次 OCI 检查均保留分配环境并由 Ascend prestart hook 注入设备/驱动 |
| sidecar | 使用同一 CANN 镜像与 `ASCEND_VISIBLE_DEVICES=void`；每代根目录全新，无 app marker、无计算设备与管理设备节点 |
| rootfsd 重启 | 运行中 Pod 保持可用，文件与双芯片计算正常；之后删除和重建通过 |
| 同路径单写互斥 | 第二个 app 创建失败；确认原 writer 的独占文件锁仍被持有，原 app 计算成功；删除双方后，相同竞争 Pod 请求单芯片成功，计数 3→4 |
| 完整公开 YAML | 仅替换节点与专用 PV 目录，原样使用公开 CANN 镜像；两代重建、单芯片计算、marker/计数与 sidecar 检查通过 |
| 正常删除与清理 | 测试 Pod、就绪测试 sandbox、关联 shim、RootPV runtime state 和 overlay 挂载均为 0；两个写层租约均 released 且锁可重新获取 |
| 环境检查 | 节点 Ready，NPU 资源恢复可分配，无 NPU 计算进程；原有平台 Pod 的 UID、phase、就绪和重启次数不变 |

计算使用 CANN `aclnnAdd`：对每个容器内逻辑设备初始化 stream、分配设备内存，执行
`out = x + 2*y`，其中 `x[i]=i`、`y[i]=2*i+1`、`i=0..255`。
同步后复制回 CPU，逐元素校验 `out[i]=5*i+2`，总和为 `163712`，最后释放设备资源。
这验证了实际 NPU 执行，不只是管理工具或设备节点可见性；不作为训练、通信或性能证据。

保留 Ascend runtime/plugin、隔离的 RootPV 测试部署和 local PV/PVC 数据供复测，所有业务测试 Pod 已删除。
测试 Webhook 仅匹配 `openfuyao.cn/rootpv-ascend-test=true` 的 namespace。

## 本地检查与边界

- `make test`、`make build`、`make helm-lint`、`make helm-template` 通过，ARM64 四个二进制构建并在线运行。
- 新 YAML 解析、容器脚本语法、文档链接、域名与敏感信息检查通过。未增加 Go 测试代码。
- 只验证上述固定版本。未升级驱动/固件，也未改变硬件分区模式。
- 资源按芯片分配；两个资源不保证同卡配对。未验证 HCCL、同卡拓扑、多机训练、vNPU、动态切分、共享超分或 CDI。
- 未验证动态 CSI、跨节点迁移、节点重启/断电恢复和性能，不从本次功能用例推导这些能力。

接入方式、驱动升级注意事项和可复用清单见 [Ascend 指南](../../../docs/user-guide/ascend.md)。
