# gVisor RootPV 隔离功能验证

日期：2026-10-20。测试环境标识、节点名、地址、私有镜像仓库、Pod UID 和原始日志仅保存在私有归档。
本记录中的组合与结果不替代完整兼容性认证。

## 固定组合

| 项目 | 实测 |
| --- | --- |
| 平台 | Linux AMD64；宿主机内核 5.10（厂商构建） |
| Kubernetes / containerd | v1.37.1 / 2.1.1 |
| gVisor | 官方 release-20261012.0，完整 tarball，SHA-512 与官方列表一致 |
| 运行时 | io.containerd.runsc.v1；原 RuntimeClass gvisor / handler runsc |
| 平台 / 内核 ABI 标识 | systrap / 4.19.0-gvisor |
| 源配置 | 显式 runtime_path、TypeUrl、ConfigPath、binary_name；grouping=true |
| Shadow | persistent-rootfs-gvisor / persistent-rootfs-runsc-v1；独立配置 overlay2=none |
| 存储 | 静态 ext4 local Filesystem + ReadWriteOnce PVC；同镜像、Strict 策略 |
| 镜像 | 预缓存 nginx 1.21.4 测试镜像；各代使用相同内容 |

## 测试方式与范围

共享环境已有 RootPV 安装，采用单个隔离 node-agent Pod，关闭 runtime-adapter-discovery 和
publish-node-capabilities；复用已有服务账号，不新建集群级角色、Webhook、Controller 或 DaemonSet，
不修改节点标签。仅在目标节点调用当前分支的发现、catalog 和 reconcile 实现，生成单一 runsc Shadow handler。
Pod 由相同 admission 库执行 mutation 与 validation，注入只读 anchor 和 adapter 证据后再提交。

因此该记录覆盖真实 gVisor、PVC、wrapper、gofer、rootfsd 与 Kubernetes Pod 生命周期；
在线 Webhook 的注册/调用及自动 inventory/catalog 控制循环不在此次集群验证范围。
这些组件的 runsc 路由和配置另有单元测试；后续仍需单独完成正常 Helm 部署的端到端验收。

## 结果

| 用例 | 结果 |
| --- | --- |
| 原生 gVisor | 普通 Pod 正常运行，使用原 RuntimeClass，无 RootPV mutation |
| 多容器 | app / sidecar 均为 gVisor，2/2 Ready；app 注入 anchor，sidecar 无 anchor |
| 持久化重建 | 共六代，计数 1→2→3→4→5→6；current UID 改变，first UID 始终为首代 |
| 最终实现复测 | 最终 wrapper 跑 5→6，CRI stats、ps 查询通过；删除后旧 runtime state 目录为空 |
| 内容与元数据 | payload、0640 权限、符号链接均保留 |
| sidecar 隔离 | 看不到 app 标记，每轮根目录标记在创建前不存在 |
| 单写者 | 第二个 Pod 因 persistent_upper_in_use 被阻止，原 Pod 数据保持可读 |
| rootfsd 重启 | 隔离 agent 重启后，原 app 内容和计数保持，后续可正常删除 |
| 最终删除 | runsc/gofer 删除后正常卸载；state 清除；lease phase=released，flock 可重新独占 |
| 原有工作负载 | 目标节点原 10 个 Pod 的 UID、phase、Ready、restartCount、containerID 均未改变 |
| 资源恢复 | 临时 Pod、PV/PVC、namespace 与 Shadow RuntimeClass 已删除；临时 wrapper/registry/config 已移除；节点标签未变 |

containerd 恢复到安装原生 gVisor 后的备份，字节比较一致；默认 runc 保持原状。
保留原生 gVisor 的独立安装、源 RuntimeClass/handler 及专用 Retain 测试数据目录，便于后续验证。
既有其他节点的 RootPV 安装和准入配置未修改。

该原生 gVisor/containerd 组合存在闲置 shim 残留：普通 gVisor Pod 删除后也可观察到，
RootPV Pod 删除后同样出现。已按测试容器 ID 核对无 task、容器元数据和子进程，
逐 PID 校验可执行文件与启动时间后定向终止，原始证据留在私有归档。
原因尚未定位；本次清理包含人工处理，不构成 shim 自动退出或完整资源回收的验收通过。

后续对照已定位为原生 shim 启动阶段缺少全局 grouping 配置，修正后的原生 Pod 可自动退出；
见 [shim 生命周期记录](gvisor-shim-lifecycle-2026-10-20.md)。上表保留首次隔离测试的实际范围和人工清理事实。
后续 [在线功能验收](gvisor-online-2026-10-20.md)已覆盖真实 Webhook/catalog 和 RootPV shim 自动退出。
